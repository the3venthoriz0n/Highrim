> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Skyrim SE SKSE mod (v0.1.0): three cooking-pot drugs (stimulant, depressant, hallucinogen), per-type addiction with escalating withdrawal, and a guaranteed overdose blackout (two doses back to back) that moves the player's gear to the hold's prison chest and wakes them naked, with a note, at a distant walkable spot, with a hangover.

**Architecture:** C++23 SKSE plugin (CommonLibSSE-NG, CMake + vcpkg) reusing the proven Sleep Together scaffold at `C:\Users\Andrew\Documents\_devWin\SleepTogether`. Items, effects, recipes, spells and notes are data in a generated ESP (`tools/make_esp.py`, Python, unit-tested by re-parsing). Pure rules live in `Core` (tested). Game-touching code (dose detection, blackout, withdrawal) is thin and logs heavily.

**Tech Stack:** C++23, CommonLibSSE-NG v15.7.3 (git submodule `lib/commonlibsse-ng`, same pin as Sleep Together), CMake, vcpkg (`x64-windows-static-md`), spdlog, MCM Helper, Python 3 (`python -I`), Lua not needed.

### Task 2: Core rules (pure, tested)

**Files:** Create `src/Core.h`, `src/Core.cpp`; Modify `tests/test_main.cpp`, `CMakeLists.txt`.

**Interfaces (namespace `Highrim::Core`, no game headers):**
- `enum class DrugType { kStimulant = 0, kDepressant = 1, kHallucinogen = 2 };`
- `bool IsOverdose(std::optional<double> lastDoseHours, double nowHours, int windowMinutes);` true when a last dose exists and `0 <= now - last <= windowMinutes/60`. Non-finite inputs or a window < 1 minute: false.
- `struct Addiction { float level[3]; double lastDoseHours[3]; double lastUpdateHours; };` (levels 0-100, `lastDoseHours` negative = never)
- `void AddDose(Addiction&, DrugType, double nowHours);` first `Decay`, then `level += 20` capped at 100, record the dose time.
- `void Decay(Addiction&, double nowHours);` `level -= 10 * elapsedDays`, floor 0; negative or non-finite elapsed time changes nothing; sets `lastUpdateHours`.
- `int WithdrawalTier(float level, double hoursSinceLastDose);` 0 if `level < 10` or `hoursSinceLastDose < 6`; else 1 if `level < 40`, 2 if `level < 70`, else 3.
- `int HighestTier(const Addiction&, double nowHours);` max over the three types (decays a copy first).
- `std::string Serialize(const Addiction&);` and `std::optional<Addiction> Deserialize(std::string_view);` versioned text (`HR1;...`), strict (any malformed input -> nullopt), round-trips exactly.
- `struct Point { float x, y; };` `std::optional<size_t> NearestIndex(Point origin, std::span<const Point> points);` (empty -> nullopt; ties -> lowest index).
- `std::optional<size_t> PickWakeSpot(std::span<const Point> candidates, Point origin, float minDist, float maxDist, float rng01);` among candidates with `minDist <= dist <= maxDist`, picks index `floor(rng01 * count)` clamped; none in band -> nullopt; `rng01` outside [0,1) clamped.
- `std::string NoteText(std::string_view prisonName);` returns `"Your things are in <prisonName>."`.

- [ ] **Step 1:** Write failing tests with the exact values above for every function: window boundaries (exactly the window is an overdose; one second over is not), decay floor and non-finite input, tier boundaries (9.9/10, 39.9/40, 69.9/70, hours 5.99/6), serialize round trip plus malformed inputs (empty, bad version, extra fields, NaN, level 101), NearestIndex ties and empty, PickWakeSpot band edges and rng clamping.
- [ ] **Step 2:** Implement; run ctest until green. Commit.

### Task 3: ESP content generator (drugs, recipes, spells, notes)

**Files:** Create `tools/make_esp.py`, `tools/esp.py` (record writer/reader), `tests/test_esp.py`; Modify `tools/make_mcm_plugin.py` (reuse its writer or merge into `esp.py`; one generator produces the final `package/Data/Highrim.esp`), `package/Data/Highrim.esp`.

**Interfaces:**
- Produces a light (ESL-flagged) `Highrim.esp` with, besides the MCM quest: three ALCH drugs, their MGEFs, three COBJ cooking-pot recipes, three withdrawal ability SPELs (tier 1-3, one set shared by all types), one hangover SPELL (ALCH-style or ability; applied by the plugin), nine BOOK notes (one per hold: Whiterun, Eastmarch, Rift, Haafingar, Hjaalmarch, Reach, Falkreath, Pale, Winterhold) with text `Your things are in <hold prison>.`, and a keyword `HighrimDrug` on all three drugs (for the later dealer feature). Fixed, documented EDIDs and a generated header `src/Forms.h` (`constexpr` local form IDs by EDID, no hard-coded numbers elsewhere).
- Drug design (names are my call): **Rimerush** (stimulant): +speed, +stamina and stamina regen for 120 s; comedown ability drains stamina regen for 60 s. **Velvet Haze** (depressant): damage resistance, slower movement for 120 s; then drowsy (reduced stamina regen) 60 s. **Dreamcap** (hallucinogen): colour/blur trip image-space effect and Detect Life for 120 s; then disorientation (blur) 60 s. Recipes: Rimerush = 2 Giant Lichen + 1 Glowing Mushroom; Velvet Haze = 2 Lavender + 1 Hanging Moss; Dreamcap = 2 Glowing Mushroom + 1 Swamp Fungal Pod. Each recipe uses bench keyword CraftingCookpot, no conditions.
- Withdrawal abilities: tier 1 slow stamina regen (cravings, shakes); tier 2 adds reduced stamina and occasional blur; tier 3 adds health regen penalty. Hangover: stamina penalty and a blur effect for one game day (24 h).

Vanilla MGEFs with image-space effects exist (look for the sleeping-tree sap and mandrake effects named in that mod) and may be referenced directly.

### Task 4: Blackout sequence (the risky part, first)

**Files:** Create `src/Blackout.h`, `src/Blackout.cpp`, `src/Prison.h`, `src/Prison.cpp`; Modify `src/main.cpp`, `CMakeLists.txt`, `README.md`.

**Interfaces:**
- Consumes: `Core::{NoteText,NearestIndex,PickWakeSpot,Point}`, `Forms.h` note IDs, `Config::Get()`.
- Produces: `Highrim::Prison::Discover()` called on data loaded: for each of the nine hold crime factions, read the faction's crime data from the game and log one info line each: faction EDID, jail container ref (the "player inventory/confiscation" chest vanilla uses when jailed), prison marker position and cell, or `missing`. `Highrim::Blackout::Run(const char* reason)` and `bool Blackout::Busy()`.
- Behaviour of `Run`: ignore when `Busy()`, when disabled, when the player is dead, or when not controllable; otherwise (1) fade to black and disable player controls, (2) choose the hold whose prison marker is nearest the player (use the exterior position of an interior's parent world position; log what was used), (3) take its confiscation chest, (4) move every non-quest, non-gold-excluded item to the chest (include gold; unequip first; verify chest counts, then remove from the player; abort and restore on mismatch), (5) pick a wake spot from candidate points in the same worldspace whose distance from that prison is between 8000 and 30000 units (candidates: player-known map markers if the game exposes them; otherwise an exterior-cell approach; the implementer records which source worked in the report), (6) teleport the player there, add the matching note BOOK, apply the hangover spell, advance game time by 6 hours, restore controls and fade in, show a message `You wake up with a splitting headache.`.
- Debug hotkey: when `iDebugBlackoutKey` is nonzero, pressing it calls `Run("hotkey")` (poll on the game thread like Sleep Together's poller, once per press).

### Task 5: Dose detection, overdose trigger, addiction state

**Files:** Create `src/Doses.h`, `src/Doses.cpp`, `src/State.h`, `src/State.cpp`; Modify `src/main.cpp`, `CMakeLists.txt`.

**Interfaces:**
- Consumes: `Core::*`, `Forms.h` drug IDs, `Blackout::Run`.
- Produces: an event sink on `RE::TESEquipEvent` for the player that recognises our three drugs when consumed (equip event of a potion base object, player actor), converts the calendar's `gameDaysPassed * 24` to hours, calls `Core::IsOverdose` (per drug-agnostic last dose time, any type) then `AddDose`, logs `Dose: <drug> addiction <levels> overdose=<bool>`, and calls `Blackout::Run("overdose")` once when overdose and `bOverdose` is on (after the drink effect has applied). `State` holds the `Addiction` under a mutex and persists via the SKSE serialization interface (unique id `'HRIM'`, version 1, load/save/revert callbacks; a corrupt record resets to zero and logs).
- When `bAddiction` is off, doses are still tracked for overdose but addiction levels do not change.
- Added after Task 3/4: `State` also persists the hangover expiry (`Blackout::Get/SetHangoverExpiryHours`, call `Blackout::TickHangover()` from the existing poller and restore the ability after load if the expiry is still in the future). After each dose the plugin casts that drug's comedown spell (`HighrimComedownRimerush`, `HighrimComedownVelvetHaze`, `HighrimComedownDreamcap`; resolve with `LookupForm(localId, Forms::kPluginName)`) when its 120 real seconds of effect have passed (poll on the game thread; a save/load or a second dose before then cancels or restarts the timer, never double-casts).

### Task 6: Withdrawal application

**Files:** Create `src/Withdrawal.h`, `src/Withdrawal.cpp`; Modify `src/main.cpp`, `CMakeLists.txt`.

**Interfaces:** Consumes `Core::{HighestTier,Decay}`, `State`, `Forms.h` withdrawal spell IDs. A poll (about every 5 seconds of real time on the game thread, only when `bAddiction` is on and the player is loaded and not in a loading screen) computes `HighestTier`; if it differs from the applied tier, remove every Highrim withdrawal spell then add the one for the new tier (none for tier 0); log each change. Re-applied exactly once after load; never more than one withdrawal spell on the player; removed immediately when `bAddiction` is switched off.
Also: while tier >= 2, or while the hangover ability is active, cast `HighrimBlurPulse` (8 s) at random intervals of 60-180 real seconds (never while a menu is open or the player is in dialogue).
